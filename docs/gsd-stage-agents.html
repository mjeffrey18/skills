GSD - stage agents

Every file under skills/gsd/references/<stage>/, resolved with gsd agents <stage>. Each card is a subagent in the skill; a dashed card runs only when its condition applies. The left column is what the main agent keeps. At most 4 subagents run at a time in any stage.

Overrides. After the skill, the agent checks ~/.agents/rules/<stage>/, then the repo's .agents/rules/<stage>/; the repo wins. CP1 Kickoff lists every override in use, from gsd agents --all. Files without mode are not agents, so review-critic's repo lenses and the project review rules (REVIEW.md) can share .agents/rules/review/.

Front matter. name, description, mode, and extends for appends. The folder gives the stage. Permissions come from the harness. Models and providers come from the topology approved at CP2. Inside T3 Code, subagents launch as T3 child tasks. Outside it, a subagent on the session's own provider and model uses the harness's own subagent tool (Claude Code's Agent tool, Codex's spawn_agent); another provider goes through the claude-code, codex or pi skill.
